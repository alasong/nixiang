# 双环嵌套接口契约 v2

**版本** v2 ｜ **级别** A 级基线（改动需评审） ｜ **日期** 2026-11-17
**取代** 契约 v0 / v1（二者仅存在于讨论记录，未落盘）

---

## 0. 本文档的地位

本文档定义**组件边界上不可自由变更的语义**。它不管实现怎么写，只管"谁可以做什么、失败时谁负责、版本怎么递"。

判断是否该写进本契约的标准：**改动它是否会导致下游返工。** 会导致的，写进来；不会的，留给实现文档。

---

## 1. 层级模型

系统是五层嵌套，每层一个"执行-观察-判定-修正"的环。层与层之间不是"同样的东西缩小"，而是职能不同：**下层执行，中层选择，上层发现。**

| 层 | 尺度 | 职责 | 交棒条件（本层放弃，交给上层） |
|---|---|---|---|
| L0 动作级 | 毫秒 | 调用工具/模型，校验返回值，重试或换备选 | 备选序列用尽 |
| L1 子目标级 | 秒 | 执行子目标，失败时局部重分解 | 重分解达深度上限 D1 |
| L2 任务级 | 分钟 | 目标形式化，收敛求解 | 无可用分支（`ReuseFailure`） |
| L3 任务族级 | 天 | 调整策略、阈值、预算分配 | 指标连续 K 天未改善 |
| L4 系统级 | 周 | 探索、发现新信号、扩张边界 | —（无上层） |

**交棒条件必须显式写死，不允许靠"感觉不对就升级"。** 判据缺失会导致两种极端：小问题触发全盘重来，或者大问题只做表面修补。

**层数由失败的可恢复性决定。** 一个失败若能在本层修好，就不建上层环。所以实施时先建 L2 + L4 两层，遇到"必须换策略才能解决"的失败再加 L3。层数是长出来的，不是画出来的。

## 2. 权限矩阵

一句话描述（"外环只写、内环只读"）会丢信息，因此用矩阵。

| 组件 | 快照 | 验证器 | 经验库 | 失败日志 | 所属层 |
|---|---|---|---|---|---|
| L4 探索 Explore | **写**（提交新 vid） | 调用 | 读中层 + 写 | 写 | 4 |
| L3 策略 Policy | 只读（当前 vid） | 调用 | **读聚合统计**（不读内容） | 写 | 3 |
| L2 收敛 Converge | 只读（单 vid，全程不变） | 调用 | 读高置信层 | 写（append-only） | 2 |
| L1 子目标 | 只读（继承父的 vid） | 调用 | — | 写（append-only） | 1 |
| L0 动作 | — | — | — | 写（append-only） | 0 |
| 路由 Router | 只读（当前 vid） | — | 读聚合统计 | — | 跨界 L2/L3 |

三条读法：

- **只有 L4 能写快照。** 其他所有层对快照只读，且 L2 及以下在一次调用内锁定单一 vid。
- **L1/L2 可写失败日志，但只能 append。** 不改快照内容、不改 vid、不影响确定性。这类写入是"记录观察到的事实"，不是"修改世界"。
- **路由与策略只读聚合统计，不读内容。** 它们看"这个族有多少条成功轨迹"，不看"某条轨迹长什么样"。这条约束保证它们的决策是纯函数、可重放、不依赖具体样本。

## 3. 三处契约

### 3.1 快照 Snapshot

| 项 | 规定 |
|---|---|
| 生产者 | 仅 L4 |
| 消费者 | L2 / L3 / 路由（只读） |
| 不可变性 | 不可变。提交即生成新 vid |
| vid 语义 | 单调递增，**标识永存不回收** |
| 内容回收 | 按引用计数。有轨迹引用则保留，无引用过 TTL 回收 |
| 时效承诺 | 提交后 **≤1h** 对内环可见（可配，B 级参数） |
| 失败语义 | L2 调用中途 vid 被替换 → 不报错、不回滚，继续用完当前 vid，下次调用再切 |

**标识与内容分开处理**是这条的关键。vid 是几十字节，永存成本可忽略；快照内容是全量事实+规则，必须按引用回收，否则一年几万个全量快照直接压垮存储。

**内环不做事务回滚。** 推理是只读的，快照中途被替换不影响正在进行的这次计算。加事务会让内环复杂度翻倍，收益为零。

### 3.2 验证器 Verifier

| 项 | 规定 |
|---|---|
| 调用方 | 全部层级共用同一个 |
| 签名 | `check(result, vid) -> Verdict` |
| Verdict | `status: pass \| fail \| unknown`<br>`kind: decisive \| scored`<br>`confidence: float` |
| 版本绑定 | 每次调用记录 `(verifier_vid, snapshot_vid)`，轨迹必须同时存这两个值 |
| 失败语义 | 超时/异常 → 返回 `unknown`，调用方按"未验证"处理（进低置信层，不进训练） |

**三态是必须的。** 只有 pass/fail 会逼着评分型验证器硬给结论，噪声全从这来。`unknown` 是一个诚实的答案：这次我没能力判定。

**硬约束：所有 result 必须可序列化持久化，且能被任意版本的验证器在不重跑任务的前提下重新判定。**

这条不满足，验证器就永远无法升级；验证器不能升级，"扩大可判定边界"这条路就断了，整个系统退化成纯成本优化。持久化失败时，该次调用降级为 `unknown`，不写经验库。

### 3.3 经验库 ExperienceStore

| 项 | 规定 |
|---|---|
| 写入者 | 仅 L4 |
| 写入内容 | 必须带 `(trace_id, snapshot_vid, verdict)` 三元组 |
| 分层 | `decisive + pass` → 高置信；`scored + pass` → 中置信；其余 → 低置信 |
| 内环读取 | 高置信层（L2） |
| 探索读取 | 高置信 + 中置信层（L4 检索 few-shot） |
| 低置信层用途 | **仅审计与重判**，不参与检索、不参与训练 |
| 失败语义 | 检索无结果 → 返回空集，调用方必须能处理"零样本"（走纯模型） |

**低置信层必须写明用途。** 只存不用的数据等于负债，最后没人维护。它的价值是：验证器升级后可重判、失败模式可回溯分析。

## 4. 全局预算守恒

嵌套带来的新约束，不可省：

```
budget(L2) ⊇ Σ budget(L1) ⊇ Σ budget(L0)
```

| 规则 | 内容 |
|---|---|
| 单池记账 | 不允许各层独立记账 |
| 自下扣减 | L0 每消耗一次，从 L1 池扣，L1 再向 L2 汇总 |
| 禁止透支 | 任何一次调用总消耗 ≤ 任务总预算 |
| 超支归还 | 下层未用完的预算归还上层，允许复用 |

**为什么必须守恒**：不守恒时 L0 的无脑重试会吃掉全部预算，而 L2 还以为自己有余量，结果是"任务看起来跑完了，预算早就超了三倍"。

---

## 5. 确定性边界

| 层 | 要求 |
|---|---|
| L2 | **必须确定**：同输入必同输出，可完整重放 |
| L1 | 允许重分解，但必须是确定性规则：同失败 → 同分支 |
| L0 | 允许重试，但必须是确定性备选序列（固定顺序），不得重新采样模型 |
| 例外 | 一旦发生非确定性行为（重新采样、温度>0），该次调用标记 `nondeterministic=true`，结果**不进高置信层** |

这条约束的实质：**内环的确定性不是靠"不重试"维持的，是靠"重试本身可预测"维持的。** 展开写清楚，实现时才不会为了"提升成功率"偷偷加一次采样，把整个可重放性毁掉。

## 6. 必须走通的场景

契约是否成立，用这五个场景验，走的过程中不需要临时拍板。

| # | 场景 | 期望 |
|---|---|---|
| 1 | 新任务，经验库空 | 走 L4 探索 → pass → 写经验 → 下次可检索 |
| 2 | 老任务，收敛失败 | L2 记负证据 → 降级 L4，不整体重规划 |
| 3 | 验证器升级 | 用旧 result + 新验证器离线重判，**不重跑任务** |
| 4 | 子目标失败 | L1 局部重分解并成功，**不惊动 L2** |
| 5 | 预算耗尽 | 逐层归还 → 优雅失败，不死循环、不超支 |

第 3 和第 5 是硬骨头：前者验证 3.2 的可重放约束，后者验证 §4 的守恒。这两个走不通，契约就不算成立。

## 7. 变更分级

| 级别 | 内容 | 流程 |
|---|---|---|
| **A 冻结** | §1 层级模型、§2 权限矩阵、§3 三处契约语义（含 result 可重放）、§4 预算守恒、§5 确定性边界 | 改动需影响分析 + 更新场景测试 |
| **B 可调** | 时效数值、路由阈值 N、预算比例、置信分层阈值 | 记录 changelog 即可 |
| **C 待定** | 目标形式化方法、跨域迁移、真值来源 | 不阻塞基线 |

A 级改动的判断标准只有一条：**会不会让已经写好的下游代码返工。** 会，就必须评审。
