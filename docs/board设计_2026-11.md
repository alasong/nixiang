# 看板设计：从 goal-tree 借什么、不借什么

**日期** 2026-11-18 ｜ **结论** 借三样（目标覆盖、开工红检、失败阻断），不借三样（依赖树、测试冻结、评审门）。

本文的每一条「goal-tree 有 X」都在源码里核过；核实手段是读 `~/.dsh/skills/ralph-goal-tree/scripts/ralphlib.py` 并用它的自检复跑。

---

## 一、goal-tree 的机制（源码定位）

| 机制 | 源码位置 | 行为 |
|---|---|---|
| 节点字段 `covers` / `out_of_scope` | `ralphlib.py:259-262` | 节点认领根目标条目；刻意不做要带理由排除 |
| 目标对账 `coverage_of_state` | `ralphlib.py:672-715` | 未认领 → `uncovered`；`ok=false` 的条件是 `uncovered / invalid_scope / assert_missing / assert_failed` 任一非空（`:713-715`） |
| `goal_done ≠ done` | `ralphlib.py:731-736` | 所有节点 done 只表示队列空；`goal_done = not gaps` |
| 开工红检（RED 门） | `ralphlib.py:10-20` | 实现改动只能落在 `test_paths` 外；`test_cmd` 必须非零；假 RED 被拦 |
| 失败阻断 | `ralphlib.py:25-26`、`:299-300` | 同指纹失败 `max_identical_failures=2` 或单阶段尝试 `max_attempts=3` → `blocked` |
| 依赖树/就绪顺序 | `ralphlib.py:725-750` | `ready[0]`，按插入顺序；有 `deps` 才有先后 |

## 二、借什么

| 借 | 理由 | 落到看板哪里 |
|---|---|---|
| 根目标拆条目 + `covers` + 缺口 | 防「拆漏了」：没人认领的目标条目必须报红 | `TASKS.md` 的「目标条目」表；`python3 -m mvp.board coverage`，有缺口退出码 1 |
| `goal_done ≠ done` | 队列清空不等于目标完成，必须单独报 | `coverage` 输出里的 `goal_done`：必须无缺口 **且** 所有认领卡都 done |
| 开工红检 | 防假任务：验收本来就能过，说明没活可干 | `board.start` 先跑一次验收；已过则拒开工 |
| 失败计数 → blocked | 防无限重试 | 任务表新增「尝试」列；连续 3 次验收不过转 `blocked` |

## 三、不借什么

| 不借 | 理由 |
|---|---|
| 依赖树 / 拓扑排序 | 树是管理成本的大头（用户实测管不好）；平面清单靠「一次只做一行」控制顺序 |
| `test_paths` 冻结 + 双测试集硬门 | 单条验收命令已够；给看板加两套测试命令是过重 |
| 评审角色 / nonce / accounting | 重；且技能自己承认「只能证明评审发生过，判不了结论真假」 |
| `split` / `unblock` / 事件流 | 复杂度；看板用「把卡改小」替代拆分 |

## 四、落地形态

`TASKS.md` v2：

- 任务表 9 列：`id / 任务 / 能力 / 覆盖 / 验收命令 / 期望 / 状态 / 尝试 / 证据`
- 目标表 2 列：`gid / 条目`
- 状态机：`todo → doing → done`，失败 3 次 → `blocked`

模块 `mvp/board.py` 新增：

- `coverage(board)` 与 `python3 -m mvp.board coverage [--json]`
- `start()` 红检、`verify()` 尝试计数与阻断
- `add(covers=...)` 校验目标条目存在


## 五、边界

- 覆盖只判「有没有人认领」，判不了「认领得对不对」——和 goal-tree 的 `assert_cmd` 一样，断言强弱靠人写。
- 红检只跑验收命令；命令本身写错（比如永远失败）会被当成合法 RED。
- 看板不做并发调度，同一时间一个 `doing`。
