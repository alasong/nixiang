# 验收反馈修复：机制通了，能力边界没通

**日期** 2026-11-18 ｜ **机制** `mvp/repair.py` + `--repair N` / `--repair-from` ｜ **卡片** T14

---

## 一句话结论

修复循环能跑、能留痕：失败内容 + 验收输出喂回模型，最多 N 轮。**离线夹具能修好；
真实模型在“恰好 20 个汉字”这种能力边界上，2 轮反馈后仍然失败。**
机制解决的是“有反馈就能改”的失败，不是“模型根本数不清字”的失败。

## 机制

- 候选验收失败 → 把任务、上次内容、验收输出一起喂回模型 → 重写内容 → 重跑外部验收；
- 最多 `--repair N` 轮；每轮落一条 `repair` 步骤（round/rc/output）；
- 离线可复现：`--repair-from JSONL` 按调用顺序给修复响应；
- 修复与否仍由外部命令判定，模型不能自评。

## 离线夹具（机制测试）

`tasks/T14-candidates.jsonl` 给一份错误内容（`nixiang 太短`），`tasks/T14-repair.jsonl`
给一份恰好 20 字符的修复结果：

```bash
python3 -m mvp.handle --task "写一行中文，恰好 20 个汉字，且包含 nixiang" \
  --out /tmp/xm-r.txt --verify "python3 tasks/T14-verify.py /tmp/xm-r.txt" \
  --candidates-from tasks/T14-candidates.jsonl \
  --repair-from tasks/T14-repair.jsonl --repair 1
# repaired=1  /  verify: pass  （T14 验收）
```

## 真实模型（能力边界测试）

同一个任务，让 DeepSeek 生成 1 份候选，失败后反馈修复 2 轮：

```bash
zsh -ic 'python3 -m mvp.handle --task "写一行中文，恰好 20 个汉字，且包含 nixiang" \
  --out /tmp/h-exact2.txt --verify "python3 tasks/T14-verify.py /tmp/h-exact2.txt" \
  --candidates 1 --repair 2 --progress'
```

读数：

| 项 | 值 |
|---|---|
| 修复轮数 | 2 |
| 最终结果 | `verify: fail`，rc=1 |
| 最后一版长度 | 24 字符（要求 20） |
| 内容 | `逆向思考这问题便能发现其中另有nixiang玄机` |

读法：反馈里已经写了 `len=24` 和 `len!=20`，模型仍然做不到精确 20 字。
这不是“没想到要改”，是“数不准 / 控不住长度”。**反馈修复对能力边界无效。**

## 可修复失败的救回率（3 任务，2026-11-18）

造 3 个“模型开头不可能知道答案、但验收失败输出会给出 expected”的任务：
读外部文件做连接/求和/倒序。模型没有读文件工具，所以初始必败；修复时把
`expected=... actual=...` 喂回，看能否照答案改对。

| 任务 | initial | repaired | 轮数 | final | 备注 |
|---|---|---|---|---|---|
| join-dash | fail | **pass** | 1 | pass | 反馈里有 expected，一次改对 |
| sum | fail | **pass** | 2 | pass | 第一轮空响应，重试后改对 |
| reverse | fail | **pass** | 1 | pass | 一次改对 |
| **汇总** | **0/3** | **3/3** | — | **3/3** | `rescue_rate=1.00` |

读法：
- **只要失败输出里带着可执行的修正信息（expected），修复就能救回**（重试后 3/3）；
- `sum` 第一轮修复返回空内容，**空响应重试（T15）后第二轮改对**——上一版记的 2/3 是
  实现缺口，不是能力边界；
- 与 `hard-exact` 的区别：那里反馈只说“长度不对”，没给目标；这里反馈直接给了答案。

## 空响应重试（T15）

修复生成本身也会失败（空响应/异常）。处理：同一轮内最多重试 2 次，仍空则放弃并保留
失败轨迹；`FileRepairer` 对空响应直接抛 `RepairError`，夹具 `tasks/T15-repair.jsonl`
第一行为空、第二行为正确内容，用来验重试路径。

## 设计判断

- 修复循环保留：对“格式漏项、忘记要点、路径写错”这类有反馈就能改的失败有用；
- 对“精确计数、复杂计算、硬性约束”这类失败，必须换手段（工具计数、结构化格式、外部校验后重排），
  不能靠多轮提示；
- 与候选选择的结论一致：**多试几次与多改几次，都解决不了稳定做不到。**

## 限制

- 真实 demo 只跑了 1 个任务、1 次；不能当普遍结论；
- 未测“可修复失败”的真实救回率（缺一批这类任务）；
- 未测多轮修复的成本与收益比。
