# RSI 调研：最新进展与趋势

**日期** 2026-11-18 ｜ **数据截止** 2026-11-03（来源自带） ｜ **判定** scored（该任务无客观真值）
**口径** RSI = Recursive Self-Improvement（递归自我改进），不是相对强弱指标

---

## 一句话结论

截至 2026-11-03，AI 在实验室内部已经承担大部分编码与实验执行，但**研究判断仍由人做**；
公开指标看不出加速，公司内部的评估（METR 对 Anthropic）首次出现约 2× 的加速信号。
关键问题不是"能不能自改代码"，而是剩下那部分研究判断能不能自动化。

## 一、三条技术主线

| 主线 | 代表工作 | 现状 |
|---|---|---|
| 自改代码 / 自演化 agent | [Darwin Gödel Machine](https://arxiv.org/html/2505.22954v2)、[AlphaEvolve](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/) | 改写自身代码库并用编码基准实测每次改动；或演化式搜索算法。最接近工程可用 |
| 自改权重 | [SEAL](https://arxiv.org/abs/2506.10943) | 模型自己生成微调数据与更新指令，用下游表现当 RL 奖励，产生持久权重更新。成本与风险都高，仍是研究 |
| 度量与门槛 | Anthropic 的 AL0–AL5、PostTrainBench / WeirdML / TasteVal / InnovationEval / CRUX 2、ECI | 进展最快的一条：把"自动化到什么程度"变成可打分、可复现的读数 |

## 二、关键数字

**实验室自报（2026-08 / 09）**
- OpenAI：每个研究员工作日对应 **3.1 个 agent 工作日**（2026-05 约 0.5）；代码行数 **7.02×**；实验数 **1.6×**。
- Anthropic：Claude 独立主导（AL4+）**26%** 的模型 R&D 任务（2026-02 不到 1%）；至少协作（AL3+）**>90%**；代码库 **90%+** 由 Claude 写；工程师日均代码量 **45×** 于 2024。

**两家都没跨过自己的门槛**
- OpenAI：GPT-6 Astra "未达 High 阈值"。
- Anthropic：2026-08 风险报告为"加速了，但没到 2×"。

**公开指标（Epoch Capabilities Index）**
- 2024-09 推理模型出现后约 **14 点/年**；过去 12 个月 **18 点**（151 → 169）；历史最大 12 个月窗口 **21 点**。
- "快年"定义为 12 个月涨 **30+ 点**（约当前速度的 2×），目前**未出现**。

**内部评估**
- METR 初评 Anthropic 内部约 **1.5×**；报告截止后发布的更新估 **约 2×（1.3–3×），约 80% 归因于 AI**。
- 仅适用 Anthropic，且含未发布模型；若该速度传导到公开模型，大致相当于一个"快年"。

**能力读数**
- PostTrainBench v1.1：人基线 51.1，前沿（Locus + Opus 5）45.6。
- WeirdML v3：GPT-6 Astra 42.2（2026-09），此前 GPT-5.6 Sol 15.0。
- TasteVal：Opus 5.5 用 **2.3× 更少算力**（95% CI 1.15–4.37）达到专家分。
- InnovationEval：GPT-6 Astra 63%，但**疑似背过原文**。
- CRUX 2（开放式研究项目，原作者评）：被评 1–2 分（Strong Reject / Reject）。

**预测面**
- LLM 集成：2030 年前出现"快年"约 **40%**；若发生，约 **70%** 归因于 AI 自动化 R&D。
- 若快年成真：专家 AGI 概率 56% → **84%**；灾难概率 2.9% → **8.4%**。
- 趋势外推："接管大部分 AI R&D 任务"在 **2027–2028**，与 OpenAI "2028-03 自动化 AI 研究员"的目标一致。
- 反方：1580 名 ML 研究者调查（2024-12）中位数 **2052** 年。中间差 25 年。

## 三、判断要过三关

[自动化 → 加速 → 广度](https://forecastingresearch.org/research/recursive-self-improvement-v1)，目前卡在三处：

1. **研究判断**：TasteVal 说"接近"，CRUX 2 说"还早"，两条证据方向相反。
2. **瓶颈**：Cunningham 等的弹性校准认为反馈环还不够强，ECI 趋势没有上弯；算力/数据/监管都可能封顶。
3. **广度**：加速可能只停在代码、数学这类可验证的窄任务，不进入需要业务判断的域。

第三点与这个仓库的结论同构：复用与自动化只在"输出空间可枚举"的地方成立。
