## 一、先把"最优"拆成三层：方法可对照、过程可机检、结果只报不判

通用任务上，结果的"最优"判不了：解空间不完备、没有精确的成本/成功率模型、没有可采纳的启发函数——
这三条也是 `docs/双引擎逆向推理设计文档.md` §1.2 拒绝"全局最优"的理由。这个判断成立，所以目标改成三层。

| 层 | 判什么 | 判据（可机检） | 明确不判 |
|---|---|---|---|
| **方法层** | 选的方法是否属于"当前已知最好"的一档 | 同模型对照：两套 harness/策略 A/B 跑同一批任务，比 Q、成本、墙钟；要求"不劣于基线且至少一项显著更好"；关键机制做消融（去掉多 Agent / 去掉逆向分解，看 Q 掉多少） | 不判"世界上不存在更好的方法" |
| **过程层** | 在预算内手段是否用尽（"尽力"） | 6 项审计清单全过：① 每个约束有对应检查；② 分解到验收可执行的最小叶子；③ 候选数/宽深达上限，或提前停止有枚举理由；④ 每次失败有归因码且不重复同一失败；⑤ 预算利用率 ≥ 阈值，未用额度有解释；⑥ 候选、评分、耗时全落盘可重放 | 不判"主观努力程度" |
| **结果层** | —— | 只报读数：通过率、Q 分、ΔQ vs 单跑基线、与 best-of-N 上界的差距、3 次方差 | 不写"最优"结论 |

**"尽力最优"的操作定义**：只有"验收全过"、"预算耗尽"、"连续 K 轮 Q 不涨（平台期）"三种收口，
停止理由必须是枚举值；"第一版就交"直接判过程不满足。

```
Q(t) ∈ [0,100]：外部判据给出（客观检查 + rubric），不接受模型自评
ΔQ = Q_best − Q_single（同模型、同验收、同一批任务）
上界估计 = N 路候选里最好的那个（best-of-N oracle），只用来算差距，不叫最优
每次运行同时记：Q、token 成本、墙钟时间、过程审计结果
```

三条硬规矩不变：验收外置（v0.1 原则 P1）；时间/成本是上限不是目标；同一任务至少跑 3 次并报方差。

**双闭环在本报告里的定义**（与现有内环/外环对齐，不另造一套词）：

| 闭环 | 周期 | 干什么 | 与现状的映射 |
|---|---|---|---|
| **A 单任务求解闭环** | 秒—小时 | 验收判据 → 逆向分解 → 并行执行 → 外部验收 → 失败归因 → 重分解/换方案，直到验收通过、预算耗尽或平台期 | 现有"内环"只做规则命中，A 把它扩成"多方案搜索 + 选择" |
| **B 跨任务进化闭环** | 天—周 | 轨迹 → 策略/规则挖掘 → 回放验证 → 激活 → 漂移监控 | 现有"外环"只挖规则，B 扩到"挖任务策略"（怎么拆、怎么验、怎么合并） |

两环的隔离照旧：探索逻辑不进 A，A 只读快照；B 的产物要回放验证后才许激活。

- 现有 BackwardEngine 是**规则树求值器**，不是"从验收目标反推子任务"的展开器；设计文档 §5.1 里的 `rank_by_gain_over_cost`、限宽限深 `W/D` 从未实现。

- 现有验证器只判"答案集合是否相等"，判不了"报告写得好不好""代码是否满足需求"；通用任务需要评分型裁判 + 客观检查的双轨。
- 现有"双环"只在演示里闭合，主路径没有在线路由（README 已知限界第 9 条）。

**工作量口径**：M0–M7 已落地（入口 + 执行器 + 分解 + 并行 + 候选选择 + 计划缓存 + 跨域压测 + rubric + 墙钟预算 + 形式化 + 校准工具）；剩下的是标注样本与真实业务数据。
没有真实模型 key 时，M2 之后的质量读数只能跑仿真，不能当结论。

## 五、可借鉴清单

**仓库内已经验证过的（直接搬）：**

1. **验收挂在节点上**（v0.1 §4.1）：移植到任务级 Goal——没有验收谓词的子目标不许执行。
2. **judgment 枚举 + 双版本号**：质量轨迹必须带 `rubric_vid`，否则分数不可追溯。
3. **不可变快照 + vid**：多 Agent 分支读同一快照，避免"各改各的"导致合并时状态错乱。
4. **预算守恒**：扩成"token + 墙钟"双账本；未用额度归还，禁止透支。
5. **哨兵/探针**：扩成质量漂移版——定期重跑已通过的任务，分数掉了就冻结当前策略。
6. **看板红检**：每张开发卡先有可执行的失败验收，再开工（这条已经在用）。

**调研里值得移植的（`docs/agent_harness调研_2026-11.md`）：**

7. **fork-and-flush**：长任务定期 fork 出"共享工作区 + 清空对话"的副本，防 idea basin；对多 Agent 就是"分支只带候选解与评分，不带全量历史"。
8. **无状态 Agent（SLA）**：状态放 harness，每次调用重建上下文；和本仓库"快照持有状态"同构，可直接用于 M2 的分支隔离。
9. **judge 与 agent 共同进化（DUET）**：评分器要版本化 + 对抗审计，否则会被"讨好评分器"的解法攻破。
10. **组件季度复审**：Anthropic 警告 harness 会编码"模型做不到"的假设；规则库与脚手架要留退出标准。

**明确不继承的：**

- "降本优先"的目标函数（README 的核心结论"降本来自不调用"）——在新需求里它是**约束**，不是目标。
- "逆向链省 2% 读取"当收益指标——对质量目标太弱；新指标是 Q 与上界差距。
- 用合成域读数当业务结论——沿用 README 已知限界 1/5/6。

## 六、目标架构（文字图）

```
任务契约（目标 + 验收命令/评分表 + 预算 C + 时限 T）
        │
   Formalizer            文本 → Goal（验收谓词 + 约束 + 子目标候选）
        │
   BackwardPlanner        从验收反推 AND-OR；限宽 W、限深 D；priority(n)
        │
   Scheduler ──► Agent × N（并行；写域互斥；各自带验收）
        │                         │
        │                    候选解 + 自证证据
        ▼                         ▼
   Selector ◄──────────── Verifier + Judge（判定型 + 评分型，双轨）
        │
        ├─ fail：归因（哪一步/哪条约束）→ 重分解（闭环 A 内循环）
        └─ pass：Recorder 落轨迹 → 策略沉淀 → 回放验证 → 激活（闭环 B）
```

四条硬约束照抄现有契约，不重新发明：内环只读快照；探索逻辑不进内环；验收外置；晋升/激活必须有回放证据。

## 八、风险与未验证

| 项 | 说明 | 处置 |
|---|---|---|
| 结果不判最优 | 只报通过率、Q、ΔQ 与 best-of-N 上界差距 | 报告口径固定为读数 + 方差，不写"最优"结论 |
| 过程指标可被凑数 | 候选数达标但同质、归因码敷衍 | 清单加"候选差异度"与"归因不重复"；5% 抽样人工看 |
| key 只在 `~/.zshrc` | 非交互 shell 读不到；`board`/`make` 里没有 | 真实模型 demo 用 `zsh -ic` 跑；卡片验收用离线候选集 |
| 多 Agent 写冲突 | 写域隔离是 advisory，不是锁 | 合并前必须过 diff 审阅；冲突记失败样本 |
| 评分型裁判会被讨好 | 判定型优先；评分型必须版本化 + 对抗审计 | 沿用 `make adversarial` 思路扩到 rubric |
| H1（任务分布）未验 | 单任务质量目标不需要 H1；内环复用是否成立需要 | 不把 H1 当本需求的开工前提，但复用率卡要报分布前提 |
| 合成域读数不可当业务结论 | 沿用 README 已知限界 1/5/6 | 所有对外数字标注数据来源 |
